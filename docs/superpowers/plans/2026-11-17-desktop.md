# Whistle Mock Manager Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement task-by-task.

**Goal:** Ship the approved macOS desktop manager with real Whistle synchronization.
**Architecture:** React workbench talks to a constrained Electron preload. Main process owns persistence, fixture compilation and official Whistle API calls. A single managed rule file contains the currently applied snapshot.
**Tech Stack:** Electron, React, TypeScript, Vite, Vitest, Playwright.
**Spec:** `docs/superpowers/specs/2026-11-17-desktop-design.md`

## Global Constraints
- macOS arm64; installed Whistle >=2.10.7; no production traffic during tests.
- User configuration stays internal, local, and recoverable; imported projects start disabled.
- Preserve existing Whistle files, selected rules and priority policy; only stop the managed file.
- Official Node API through main process only; context isolation, sandboxed renderer and bounded IPC.
- Draft saves do not change active responses; explicit Apply; closing the app preserves applied rules.

## Review Focus
- Whistle single-select mode would deselect existing rules: synchronization refuses until UI setup.
- JSON/files changed after Apply would leak drafts: versioned content paths and immutable active fixture verification.
- Concurrent save/apply overwrites newer metadata: serialized operations and monotonic UI saves.
- Imported IDs/paths or rule syntax can escape intended mapping: validate IDs, reject line breaks, exact escaped URL matching.
- Partial sync fails after writing rules: report failure, preserve last-good snapshot and expose explicit recovery.
